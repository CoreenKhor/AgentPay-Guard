# Autonomous Agent Wallet Security Standards

Autonomous AI agents must never hold raw master private keys directly inside their execution memory or LLM context windows. This skill details the security model for non-custodial agent treasury delegation.

## 1. Threat Model & Key Exposure Vectors

1. **System Prompt Leakage / Jailbreak:**  
   If an agent's private key resides in runtime environment variables exposed to the LLM context or tool calling space, adversarial prompts can compel the model to output the raw base58 key.
2. **Recursive Tool Invocations:**  
   Cognitive loops caused by ambiguous tool feedback can trigger repeated spend calls until the wallet balance drops to zero.
3. **Transaction Malformation & Blind Signing:**  
   Signing uninspected transaction buffers generated by probabilistic model outputs allows malicious external agents to siphon funds via parameter manipulation.

## 3. Best Practices for Agent Wallet Implementations

1. **PDA-Based Custody:**
   - All operational funds are locked inside a program-owned PDA derived from `[b"vault", agent_id]`.
   - Transfers cannot occur via standard Ed25519 signature of a hot key; they strictly require program execution through `agentpay_guard::settle_payment`.

2. **Ephemeral Session Keypairs:**
   - When hot keys are strictly necessary for signing transactions, use ephemeral session keys with:
     - Short validity windows (e.g., 10 minutes).
     - Bounded aggregate spend limits.
     - Single-recipient allowlist constraints.

3. **Air-Gapped Signing Interceptor:**
   - The signing module must run in an isolated process outside the LLM execution memory.
   - The LLM outputs an intent structure (JSON schema); the interceptor validates this structure and signs the Solana instruction only after all Guard checks pass.

4. **Emergency Kill-Switch (Circuit Breaker):**
   - Provide an independent `sentinel_authority` keypair (held by a monitoring daemon or multisig) capable of executing a freeze instruction that halts all vault disbursements without needing the master key.

---

## 4. Security Verification Checklist

- [ ] Private keys are never passed into system prompts, tool schemas, or logging frameworks.
- [ ] Programmatic accounts cannot transfer SOL/SPL tokens without invoking the verification program.
- [ ] Agent vault PDA bump is deterministically bound and validated on-chain.
- [ ] Emergency freeze can be triggered independently of agent reasoning state.
- [ ] Treasury balance alerts are dispatched to operators when balance dips below operational thresholds.
